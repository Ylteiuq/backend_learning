## 1. 使用与维护方式

### 学习目标

以现有用户与任务业务为练习载体，同时推进三条学习主线：

| 主线 | 需要提升的能力 | 项目中的练习载体 |
|---|---|---|
| C++ 语言与标准库 | 对象生命周期、参数传递、移动语义、lambda、智能指针、RAII、模板、容器与线程同步 | Service/Controller 的回调、Mapper、WorkerQueue、测试事件循环 |
| Drogon 框架 | 请求路由、配置、ORM、事件循环、异步响应、Filter 与协程接口 | 用户与任务接口、delay/primes 实验 |
| 后端开发 | HTTP 语义、业务规则、数据库一致性、认证授权、测试与排查 | 用户 CRUD、任务归属、事务与独立测试环境 |

每项任务明确一个主要学习概念，并尽量将 C++ 写法与框架行为、后端需求联系起来。例如，创建任务既能学习外键与竞态，也能学习 lambda 初始化捕获、mutable、std::move 和异步所有权。

允许围绕一个语言特性停下来阅读代码、修改局部写法或做独立小实验，即使没有新增接口也可以完成一次有效学习。工程整理用于支持这些练习；投入根据当前理解薄弱点决定。面试讨论可以作为额外检验方式，不作为已确认的主要目标。

一项学习任务完成需要三个证据：

1. **能运行**：正常流程和关键错误路径符合约定。
2. **能解释**：学习者能用自己的话说明机制、取舍和适用条件，并解释涉及的 C++ 对象由谁持有、何时复制/移动、何时销毁。
3. **能验证**：有可重复的测试或检查步骤；语言特性可用最小编译示例、生命周期日志或局部实验验证。

代码存在、测试通过、学习者掌握是三个不同状态。本文记录了前两项的核对结果；目前没有足够的问答记录判断学习者对各概念的掌握程度，不以提交数量代替这一判断。

## 2. 当前进度：实现、覆盖与掌握分开记录

### 2.1 业务接口

下表中的 `{id}` / `{userId}` / `{taskId}` 是面向读者的路径参数名；代码使用 Drogon 的 `{1}` / `{2}` 占位符。

| 接口 | 已实现的行为 | 现有自动化覆盖与缺口 |
|---|---|---|
| `POST /users` | JSON、必填字段和类型检查；成功返回 201 与模型 JSON | 非法 JSON、缺 age、创建后查询；未覆盖姓名和年龄的业务边界 |
| `GET /users/{id}` | 正整数 ID 校验；找到返回 200，未找到返回 404，数据库错误返回 500 | 非数字 ID、指定缺失 ID、创建后查询；未逐一覆盖 ID 边界和数据库故障 |
| `GET /users` | page/per_page 分页；按 ID 排序；per_page 上限 100；偏移溢出检查 | 默认参数、部分合法/非法边界、顺序检查；缺固定数据集下的页内容验证 |
| `PUT /users/{id}` | 完整提交 name/age；成功 204；影响行数为 0 时 404 | 重复更新、读回数据、部分非法请求、已删除用户 |
| `DELETE /users/{id}` | 成功 204；不存在返回 404 | 用户生命周期、重复删除与非法 ID |
| `POST /users/{userId}/tasks` | 先查询 owner，再插入任务；title 不能是空白；成功 201 | taskCompletionTest 覆盖正常创建；创建接口的完整错误矩阵尚未覆盖 |
| `GET /users/{userId}/tasks` | 先查询 owner，再按 task ID 排序返回列表 | 正常列出任务；空列表、缺失 owner 等缺少独立用例 |
| `PATCH /users/{userId}/tasks/{taskId}` | completed 必须是 JSON bool；单条 UPDATE 同时匹配任务与 owner；成功 204，否则 404 | 重复设值、读回、路径 ID 与请求体错误、归属不匹配、已删除 owner |

任务模型的 completed 当前输出为整数 **0/1**，PATCH 输入要求布尔值；这是现有接口约定，需要在 API 文档中明确，后续可再决定是否统一。

### 2.5 本对话已记录的学习证据

- **值捕获**：学习者正确预测字符串按值捕获后会输出 Alice，即使原字符串后来改成 Bob。按其要求跳过运行。曾把原对象销毁归因于引用捕获；已解释原对象在两种捕获方式下都于作用域结束时销毁，引用不延长其生命，后续独立应用仍待观察。

## 3. 当前架构与入口

业务请求链路：

```text
HTTP 请求 → Drogon 路由 → UserController
                           ├─ 解析参数、检查 JSON、转换 HTTP 响应
                           └─ UserService / TaskService
                                └─ 异步 Mapper → SQLite
                                     └─ 成功或错误回调 → HTTP 响应
```

异步实验有独立链路：AsyncController → 定时器 / WorkerQueue → 回调响应；计算统计通过 mutex 保护。

| 文件或目录 | 作用与当前约束 |
|---|---|
| `main.cc` | 加载相对路径 config.json，启动 advice 启用并检查外键，代码中监听 0.0.0.0:5555 |
| `config.json` | 实际配置：SQLite 相对路径 drogon_backend.db；1 个连接，is_fast=false；1 个 IO 线程 |
| `config.yaml` | 模板配置，当前 main 不加载 |
| `controllers/UserController.cc` | 用户与任务的 HTTP 处理、输入检查、错误映射；含生命周期观察日志 |
| `services/` | 接收业务参数与回调，持有 DbClientPtr，不接收 HTTP 请求；Mapper 调用位于这一层 |
| `models/` | 生成的 Users/Tasks ORM 模型；model.json 指向 users/tasks 表 |
| `migrations/` | 两份建表 SQL；tasks 含外键、ON DELETE CASCADE、completed CHECK 与 user_id 索引 |
| `utils/`、`experiments/` | WorkerQueue 实现与独立演示；主服务与 WorkerQueueDemo 均编译队列实现 |
| `test/test_main.cc` | 7 项 HTTP 集成测试，硬编码访问 127.0.0.1:5555 |
| `test/config.json` | 存在，但现有测试 main 没有加载它；文件存在不表示测试数据库已隔离 |
| `CMakeLists.txt` | 主服务、WorkerQueueDemo 与 HTTP 测试；已移除 MiniBackend 的构建依赖 |

当前规模可以保留 Service 直接使用 Mapper 的设计。出现数据访问复用、业务规则复杂化或替换存储的实际需求时，再评估 Repository；这是学习建议，不是需要机械执行的分层要求。

### 5.2 修改前需要理解的机制

1. **异步对象生命周期**：Controller 内的 Service/Mapper 是局部对象，不能假定回调执行时它们还存在。TaskService 的后续回调按值保存 DbClientPtr、业务值和下游回调，不捕获局部 Service 的 this。需要学习的是回调所需对象的所有权，不是背诵固定写法。
2. **日志顺序不是时序保证**：A/B/C/D 在 UserController::getById，不在 TaskService。异步数据库回调可能与 handler 的后续语句并行；即使观察到 D 在 C 之前，也不能写成所有请求固定如此。保留或移入实验，待能解释观察后再整理日志。
3. **回调副本与响应次数是两件事**：先复制 error 分支回调再移动 success 分支，避免使用已移动的 std::function；恰好响应一次仍依赖每条控制流及底层回调约定。复制本身不能防止重复响应，错误响应后应结束对应分支。
4. **数据库存在性与一致性**：创建任务先查 owner，再插入，中间仍可能被删除。FK 是最终数据约束；当前 Controller 将查找失败或 ForeignKeyViolation 映射为 404。Drogon 1.9.13 SQLite 驱动提供该异常映射，但本次没有复现这条竞态路径。[对应版本驱动源码](https://github.com/drogonframework/drogon/blob/v1.9.13/orm_lib/src/sqlite3_impl/Sqlite3Connection.cc)
5. **外键是连接设置**：在一个连接上启用 PRAGMA 不等于初始化整个连接池；当前单连接配置与检查有效，不能直接推广到多连接或其他客户端模式。[SQLite 官方说明](https://www.sqlite.org/foreignkeys.html#fk_enable)
6. **任务归属条件不等于身份授权**：`id AND user_id` 的单条 UPDATE 保证任务属于 URL 指定的用户，避免先查任务再更新的间隙；尚无机制证明请求者就是该用户。授权要以后从可信身份取得 userId，并验证访问权。
7. **幂等性不等于多语句事务**：重复 PUT/PATCH 得到相同最终状态是接口语义；多条写入全部成功或全部回滚是另一个能力，当前尚无显式事务练习。
8. **统计值的边界**：completed 在计算结束时增加，发生于构造/回传 HTTP 响应之前；它不是客户端成功收到响应的数量。queued 是逻辑差值，还包含已记 submitted、尚未实际入队或已取出但尚未计 running 的短暂窗口。现有锁保障共享计数访问；W2 的容量与 PostResult 拒绝回滚已验证，尚无取消和任务异常补偿机制。容量判断使用队列锁下的 tasks_.size()，不能用 stats 的 queued 推断可接收数量。
9. **WorkerQueue 的停止约定**：stop 由拥有者线程调用，等待已接受任务执行完；现有演示验证顺序重复 stop。不能由此声称多个线程同时 stop 或工作线程调用 stop 都安全，也不能推断框架队列具有相同语义。

不使用“无 P0，所以全部功能正确”作为审查结论。本次未发现已测正常流程的阻断问题，但明确存在可复现的初始化和业务规则缺口；未测试的分支保持待验证。

- **结构**：readSqlFile(path) 负责读取并报告文件错误；executeSql(db, sql, context) 执行并报告 SQL 错误；main 校验两个参数，依次读取 001_create_users.sql、002_create_tasks.sql，打开数据库并立即交给 RAII 持有，启用工具连接外键，再依次执行两份脚本，成功退出 0、失败 catch 后 return 1。
- **SQLite 接口**：已核对本机 sqlite3.h 和官方 sqlite3_exec 文档，exec 可执行完整的多语句脚本；不要用字符串按分号拆 SQL。open 即使失败也可能产生句柄，检查返回值前先用 unique_ptr 接管，错误信息在句柄有效时复制。exec 的 errmsg 参数使用 nullptr，通过 sqlite3_errmsg 获取信息，避免额外错误字符串释放。
- **验收**：新临时数据库具有 users/tasks/idx_tasks_user_id；插入一条用户后再次初始化仍保留它；缺失 SQL 文件、SQL 语法错误或数据库无法打开时显示上下文且非零退出；只使用临时数据，不触碰开发库。
- **边界**：IF NOT EXISTS 只支持当前初始 schema 的重复建表，不能升级旧表；本轮不实现迁移版本管理或跨脚本全部回滚。工具连接的 PRAGMA 不替代 Drogon 连接的设置，保留现有 startup advice。之后再选择配置路径/独立服务测试或事务练习，不把本工具当作这些能力已完成。

A2/A3 结合 promise/future、容器、对象生命周期或资源清理学习；具体使用什么机制根据实现方案决定。
